# FUJI CLIMB

実測の標高タイル（DEM）をそのまま地形にした 3D クライミングゲーム。第一弾は**富士山**。

地形は実データ、見た目は**標高と傾斜から手続き的に生成**しています。航空写真タイルを
一切ダウンロードしないので軽く、テクスチャ用の通信もメモリも要りません。

```bash
npm install
npm run dev      # http://localhost:5173
```

## 遊び方

WASD で移動、マウスで視点。剣ヶ峰（3776m）を目指します。

| キー | 動作 |
| --- | --- |
| `W` `A` `S` `D` | 移動 |
| マウス | 視点 |
| `Shift` | 登攀。38°を超える斜面を登るのに必要。消耗が激しい |
| `R` | 休憩。静止して体力を早く回復 |
| `Space` | ハーケンを打つ。滑落を止める支点になる（急斜面でのみ可） |
| `E` | 酸素ボンベ。60秒間 高度の影響を打ち消す |
| `C` | 俯瞰カメラ |
| `Esc` | ポーズ |

### 登攀のルール

足元の傾斜と、**進もうとしている方向の勾配**は別物です。同じ壁でも、まっすぐ登れば
急勾配、斜めにトラバースすれば緩勾配になります。これがルート取りの基本です。

- **体力** — 移動で減り、勾配が急なほど速く減る。静止で回復、`R` の休憩でさらに速い
- **握力** — 45°を超える斜面にいる間だけ減る。緩い場所に戻れば回復する
- **滑落** — 握力が尽きて 42°より急な斜面にいると滑り出す。斜面が緩むまで止まらない
- **ハーケン** — 打っておくと、滑落してきたときに引っかかって止まる
- **高山病** — 2500m から回復量が落ち、3500m を超えると静止していても消耗する
- **風** — 高度とともに強まり、消耗と画面の揺れが増す

## 標高タイルについて

起動時に**タイルの形式を自動判定**します。サーバの仕様を知らなくても動きます。

1. `https://armd-01.sakura.ne.jp/tiles/` 配下の URL パターンを順に試す
2. 画像が取れたら Terrain-RGB / GSI 標高タイル / Terrarium の各方式でデコードし、
   「富士山の標高としてありえる値」になった方式を採用する
3. どれも駄目なら国土地理院の公開タイル（`dem5a_png` → `dem_png`）にフォールバック

タイトル画面の「詳細設定」から URL テンプレートとデコード方式を直接指定することもできます。

> **注意**: ブラウザから読む以上、タイルサーバが `Access-Control-Allow-Origin` を
> 返す必要があります。CORS ヘッダが無いとピクセルを読み出せず（canvas が汚染される）、
> そのソースはスキップされます。

デコード方式（`src/terrain/decoders.ts`）:

| 方式 | 標高 |
| --- | --- |
| Terrain-RGB | `-10000 + (R*65536 + G*256 + B) * 0.1` |
| GSI 標高タイル | `x = R*65536 + G*256 + B` を符号付き24bitとして `* 0.01` |
| Terrarium | `R*256 + G + B/256 - 32768` |

## 構成

```
src/
  geo/mercator.ts        Webメルカトル ↔ タイル座標、ローカルENU平面
  terrain/
    decoders.ts          標高PNGのデコードと妥当性スコアリング
    TileSource.ts        URL総当たり + 形式の自動判定
    HeightField.ts       タイルを1枚の高さ格子に貼り合わせ、任意座標を補間
    TerrainLOD.ts        四分木LOD + スカートによるクラック処理
    terrainShader.ts     標高と傾斜から地表の色を作るシェーダ
  game/
    routes.ts            山とルートの定義
    Climber.ts           登攀シミュレーション（体力・握力・滑落・高度）
    Input.ts             キーボード/ポインタロック
  world/Scenery.ts       天球・雲海・ランドマーク・山頂ビーコン
  ui/                    HUD とスタイル
```

### 地形メッシュ

プレイ範囲（14km 四方）を四分木で分割し、プレイヤーに近いノードほど深く割ります。
葉 1 枚は常に 32×32 の格子なので、描画頂点数は範囲の広さではなく四分木の深さ、
つまり距離の対数でしか増えません。実測で **277 葉 / 約 64万三角形**。

分割深度が違う葉が隣り合うと辺に隙間が出るので、各葉の外周に下向きの
「スカート」を付けて塞いでいます。

## テスト

```bash
npm run build
npm test
```

実タイルサーバに繋がず、**富士山を模した円錐を国土地理院 dem_png 形式の PNG に
合成して注入**し、タイル取得 → デコード → 貼り合わせ → 座標変換 → メッシュ生成 →
登攀 → 登頂までを実ブラウザ（Playwright + Chromium）で通します。43 項目。

標高は解析モデルと突き合わせるので、メルカトル変換やタイルの貼り合わせがずれると
検出できます。三角形の巻き順と実際の描画ピクセルも検証しており、地表が裏返って
カリングで消える事故を防ぎます。
